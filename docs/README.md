## 设计核心结论（摘要）

1. **服务器定位**：BeChat 是提供基础原语（注册、登录、消息、群聊等）的服务端，业务编排逻辑由客户端设计。
2. **连接模型**：每个 TCP Session 只处理一条命令即断开（类似 HTTP）；用户是否在线完全由 UDP 心跳判定；服务端不主动推送，客户端通过 Poll / PullGroupHistory 拉取消息。协议预留长连接扩展点。
3. **内存状态**：BeChat 在内存中持有用户注册信息、在线用户信息、群聊历史消息，以及在线用户的私聊待收队列（投递缓冲）；**私聊消息不作为历史保存**。所有状态不持久化，服务器重启即清空。
4. **心跳机制**：客户端与 BeChat 之间通过独立的 UDP 通道发送心跳；BeChat 超过 30 秒未收到某用户的心跳，即判定该用户断开连接。
5. **技术基线**：standalone Asio（非 Boost）+ 自定义 TLV + C++20，内存存储，不引入数据库。
6. **近期第一步**：先固化协议（Length 保持 u16）、编解码器、分发器、写队列和 strand，补齐测试，之后进入身份/心跳、消息与群聊历史。

## 与上一版设计的关系

上一版设计把“无状态”理解为“服务器不保存任何业务数据”。经确认后修正为：**BeChat 在内存中是有状态的**（注册信息、在线信息、群聊历史、私聊待收队列），但状态只存在于内存、不做持久化、不依赖外部组件；连接模型为单命令短连接，在线状态完全由 UDP 心跳判定。
