# BeChat 实施路线图

## 阶段总览

| 阶段 | 版本 | 目标 | 完成标志 |
|------|------|------|----------|
| Phase 1 | v0.2 | 协议内核 | 单请求短连接、编解码/分发/写队列/strand/测试齐全 |
| Phase 2 | v0.3 | 身份、在线与心跳 | 注册/登录/令牌/在线表/UDP 心跳与 30 秒超时判定 |
| Phase 3 | v0.4 | 消息与群聊历史 | 私聊待收队列与 Poll、群管理、群聊历史、离线回补 |
| Phase 4 | v0.5 | 加固与交付 | 配置、资源限制、优雅停机、示例客户端、文档完善 |

每个阶段结束都要求：`-Werror` 下零警告编译、CTest 全绿、日志可追踪。

## Phase 1：协议内核（v0.2）

目标：把“TLV echo”升级为“可扩展、可测试的短连接协议内核”，**不引入业务状态**。

任务：

1. 协议定稿（Length 保持 u16、Type 表、响应位、状态码、单请求短连接语义），更新 `docs/protocol.md` 与 `docs/test_cmd.md`；
2. 实现 `TlvCodec`：头部编解码、`max_payload` 校验、请求对象解析；
3. 引入 `Dispatcher`：Type → handler 注册表，默认 handler 返回协议错误；
4. 重构 `Session`：读一条命令 → 分发 → 写响应 → 关闭；写队列 + strand；`mode_` 字段预留长连接；
5. 引入 `IoContextPool`：N 个 io_context、每连接 round-robin 分配；
6. 统一 `Close(reason)` 关闭流程；
7. CMake 显式声明 Asio/spdlog 依赖；把核心代码拆为 `bechat_core` 库，`bechatd` 只保留 main；
8. 补测试：codec 边界（0 长度、超限、截断）、Dispatcher 路由、单连接单命令（第二条命令被忽略）、双客户端并发短连接。

验收标准：

- `nc` 发送协议格式报文可得到响应或明确错误，响应后连接关闭；
- 超限包、未知 Type 会得到 `0x0002` 并断连；
- 同一个 TCP 连接只处理一条命令，不循环处理后续数据；
- 两个并发客户端互不干扰，短连接风暴下无资源泄漏。

## Phase 2：身份、在线与心跳（v0.3）

目标：建立“注册表 + 在线表 + UDP 心跳”三大基础能力，在线判定完全以心跳为准。

任务：

1. `AuthService`：内存注册表（用户名 → 加盐密码哈希）、Register/Login；
2. HMAC 令牌：签发、验证、过期（payload 含用户名与时间）；
3. `OnlineTracker`：登录登记、Logout 移除、心跳更新；
4. `UdpHeartbeatReceiver`：同端口 UDP 绑定、心跳包解析、token 校验、`last_heartbeat` 更新；
5. 心跳超时扫描定时器：5 秒扫描、30 秒超时判定离线；
6. 配置项：心跳间隔/超时/扫描周期、令牌有效期；
7. 测试：心跳保活、心跳停止 30 秒离线、TCP 连接断开不影响在线、伪造/过期 token 被丢弃、重新 Login 换 token 不中断在线。

验收标准：

- 未登录用户的心跳包被忽略；登录用户心跳正常则一直在线；
- 停止心跳 30 秒后被判定离线；
- TCP 连接每次用完即断，在线状态不受影响；
- 服务器重启后注册表与在线表清空（符合不持久化原则）。

## Phase 3：消息与群聊历史（v0.4）

目标：实现私聊轮询、群管理、群聊历史与回补，验证“短连接 + 心跳在线 + 轮询拉取”的模型。

任务：

1. `RelayService`：私聊入队（仅在线接收方）、Poll 出队并清空、队列上限逐出；
2. `GroupManager`：CreateGroup/JoinGroup/LeaveGroup、成员校验；
3. 群聊流程：SendGroup 写历史（分配 seq）→ SendGroupResp 返回 seq；
4. 群历史存储：deque 上限（默认 1000 条/组）、最旧逐出、重启清空；
5. `PullGroupHistory`：按 `after_seq` 增量拉取、按报文空间截断、翻页；
6. 示例客户端：注册 → 登录 → UDP 心跳 → 私聊（发送 + Poll）→ 建群/加群 → 群聊 → 断线重连拉取历史；
7. 测试：私聊在线入队与 Poll 清空、离线不缓存、心跳超时丢队列、群历史写入与逐出、掉线成员按 seq 回补、并发群聊无串包。

验收标准：

- 接收方在线时，私聊进入其待收队列，Poll 一次拉取后队列清空；
- 接收方离线时发送方收到 `0x000B`，服务器不保存；
- 群成员发消息后，其他成员通过 PullGroupHistory 能拉到该消息（含 seq）；
- 掉线期间错过的群消息，重连后通过 PullGroupHistory 完整追平（在历史保留范围内）；
- 群历史超过上限时最旧消息被逐出，seq 不回绕；
- 100 并发连接（每个连接一条命令）无串包、无崩溃。

## Phase 4：加固与交付（v0.5）

目标：把原型变成可稳定运行、可配置的服务端。

任务：

1. 配置：监听地址、TCP/UDP 端口、线程数、心跳参数、`max_users`/`max_online`/`max_groups`/历史上限/待收队列上限、日志级别；
2. 资源限制：最大连接数、`max_payload`、单条 content 上限、写队列深度上限、单请求读取超时；
3. 优雅停机：SIGINT/SIGTERM → 停止 accept 与 UDP 接收 → 等在途响应写完 → join；
4. 日志完善：连接生命周期、心跳超时、队列逐出、原语统计；
5. 打包：install/CPack 规则补全（库、头文件、`bechatd`）；
6. 文档收尾：README 使用说明、协议文档与实现一致性检查。

验收标准：

- 单进程可配置化部署，Ctrl-C 可在 2 秒内干净退出；
- 短连接风暴（大量连接频繁建立/断开）不拖垮服务器；
- 打包产物可直接在干净环境运行。

## 后续演进（超出当前范围，仅记录）

| 方向 | 说明 |
|------|------|
| 长连接模式 | 使用预留的 0x00F0–0x00FF 协商原语，连接处理后不关闭并恢复 Push 推送；协议已预留扩展点 |
| 持久化 | 用户/群/历史落盘，或接入数据库；与“不持久化”基线冲突，需另行决策 |
| 私聊历史/离线缓存 | 在服务器保存私聊消息；与“私聊不保存”冲突 |
| 删群/踢人/群公告 | 群管理扩展，需新增原语 |
| TLS | 证书管理与配置，适合公网部署时引入 |
| 多进程/多节点 | 在线路由与群历史需要一致性存储，与“不引入组件”冲突 |
| 消息分片/大文件 | 协议扩展，突破 64 KiB 单包限制 |
| 限流/防滥用 | 独立策略模块，可在 v0.5 后按需添加 |
| 客户端 SDK | 协议稳定后，example 客户端可抽成独立仓库 |
